# Contributing to COS_

## Branching rule
- Each new task starts on a dedicated branch.
- Suggested naming: `task/<short-scope>`.

## Commit rule
- Commit often.
- Prefer small, reviewable commits with a single clear purpose.
- Use conventional prefixes such as `feat`, `fix`, `refactor`, `docs`, `test`, `chore`.

## Task completion rule
- A task is complete only when the branch is ready for a pull request.
- The PR should describe the scope, tests run, and any remaining risks.
